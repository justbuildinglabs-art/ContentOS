# ContentOS 0.6.1: decisions made during implementation

Every ruling made on Leslie's behalf while building 0.6.1 (plan `docs/superpowers/plans/2026-09-24-claude-search-first.md`, 2026-09-24), in order, then the click-through on sample data. Each ruling ends with what it costs if it was wrong. Revisit any of them by editing the code or the spec; nothing here is load-bearing beyond what the tests pin.

## During the tasks

- R1: Tasks 4 and 5 could leave `PageTests.test_the_page_calls_every_route_and_sends_the_token` red, because the page cannot call `/api/search-again` before Task 6 rewrites it. Task 6 turned it green. Cost if wrong: one known-red test across two task reviews.
- R2: the page reconnects after Search again by reloading itself once the resumed panel answers, and `start(state)` re-renders from that state. The spec's "re-renders from that state" is met. Cost if wrong: a full-page reload flicker instead of an in-place refresh.
- R3: Task 8 Step 6 (the browser click-through on sample data) was left to the controller after the workflow, because subagents may lack the browser tools. It is recorded below. Cost if wrong: none.
- R4: implementer and reviewer seats cannot be resumed inside a workflow, so every fix round was a fresh implementer carrying the brief, the report, and the findings. Cost if wrong: a little more re-reading per round.
- R5: items a task reviewer could not verify from its diff went to a resolver holding the plan and spec, and confirmed gaps entered the fix loop. Cost if wrong: a resolver misjudges a cross-task gap that the final review then has to catch.

## After the final review (minor findings and the deferred click-through)

- The CLI's check-only refusal keeps the exact text the spec pins ("Check-only needs at least one handle from Claude's search or typed in."). Only the panel's words changed: "To check only Claude's finds, add at least one creator first, or tick Also search Instagram for more creators.", shown in place of $0.00 when a check-only scan has nothing to check. Cost if wrong: the chat sees slightly off wording ("typed in" seeds are not checked in check-only) until the spec changes.
- The idle handoff keeps the dials the page last sent (`page_settings`); the idle `RESULT` keeps the last run's `settings`, as in 0.6.0. `/api/state` still reports the last run's dials, so a plain tab reload shows those. Cost if wrong: a reload resets the dials the creator moved without running.
- The panel's generation is a random value per `ui` process, not a counter carried in the handoff. A fresh panel already gets a new token, so only a resumed panel shares a token with an old page, and any new process gets a new generation. The check covers `/api/estimate` and `/api/search-again`, the two routes that record the page's cards. A payload with no generation (tests, other callers) is not checked. Cost if wrong: a stale tab's Run still scans its own list of finds.
- A fresh `ui` removes any old handoff once it has bound. The optional 24-hour age limit on a handoff was not added: an idle panel's handoff is meant to reopen the next day, and the fresh-panel rule already retires stale tokens. Cost if wrong: a handoff can be resumed however old it is, until a new panel starts.
- `ui --resume` takes `mock` from the handoff; `--mock` on a handoff that ran on real data exits 2. A handoff with no `mock` key falls back to the flag. Cost if wrong: none found.
- The click-through found one more thing, fixed with a test first: a card that missed the bar showed both "About 48K followers, per ..., not checked" and the measured "52K followers". The stated count now gives way once the scan measured the account.

## Second fix wave (the final reviews' Important findings)

- A resumed panel keeps the handoff's token only when it binds the handoff's own port. A taken port, `--port`, or a handoff with no usable port gets a new token, because the waiting page kept sending the old token to the old port. The spec's "its token (so the open page's link still works)" still holds on the same port. The waiting page reloads only onto a panel with a new generation, and stops calling an address whose answer is not a panel's ("Another program answered at this address. Ask Claude for the new link."). Cost if wrong: after a port fallback the old tab needs the new link, which the skill already hands over. A process that binds the old port, reads the token, and lets the port go before the panel resumes is not covered; a same-user process can read the 0600 files anyway.
- Past 120 cards, the trim keeps ticked cards first, then cards that are not removed, then removed ones, in page order. The page does not cap scan additions (that would hide passed creators); it says how many creators the panel keeps and how many unticked ones will not be kept. Cost if wrong: removed cards past the limit drop out of `known`, so a later Claude search may suggest them again.
- A resumed panel whose `discovery.json` cannot be read, or is not the shape the page reads, opens idle with the note "The last scan's results could not be read, so they are not shown. Run the scan again to see them." Cost if wrong: none found.
- A first open skips finds that are on the watch list, typed as seeds, or format accounts, as `merge_finds` already did on resume, and the banner names them. The creator's own handle is only skipped when it was passed as a seed; the skill tells Claude to leave it out of the finds. Cost if wrong: a creator who wanted a format account as a competitor adds it by hand.
- "shortlist full", "not checked in time", and "not measured in time" read "Not checked: over your Creators to check limit" or "Not checked: ran out of time", with no missed-the-bar warning, and count as unchecked picks. This departs from the spec's list of "Missed:" reasons, which named "not checked in time"; the left-out summary still lists them as before. Cost if wrong: one wording to change back.
- Pre-flight's stop on a missing key no longer covers `/contentos discover` and `/contentos setup`. The spec's skill section still says pre-flight "stops unless `--mock`"; its "0.6.1 changes" say Save never needs a key, and the skill follows those. Cost if wrong: a keyless creator hears about the key once, later, only when they want the scan.
- The panel's `RESULT` bullets now go: saved true (twice), `next`, `reason: idle`, plain `saved: false` (Close), no `RESULT`. The idle reopen is spelled out: in the background, `--resume --open`, no `--handles-file`, hand over the `UI <url>` link, wait the same way.
- R6 (controller): the final review's step that tried to refute each finding crashed (a script bug in the controller's workflow), so the eight Important findings above first skipped that check and the first fix wave. They went through it afterwards (three independent checks each: six confirmed 3 of 3, two confirmed 2 of 3) and got their own fix wave and scoped re-review. Cost if wrong: one fix wave beyond the process's one-wave rule, spent on findings the reviewers had already reproduced.
- The spec now records the "Not checked" status and the keyless pre-flight for discovery (commit 17ac8ce), so it matches the two rulings above. Cost if wrong: two spec lines to change back.
- Residual, not fixed (a same-user local process is needed): the waiting page still sends the old token to the old port while Claude searches. A process that takes that port, reads the token, and lets the port go before `ui --resume` runs would hold a token the resumed panel reuses on the same port. Closing it means either polling without the token or never reusing it, and never reusing it breaks "the open page's link still works". A process running as the same user can already read the 0600 files. Cost if wrong: that process could run a scan or save picks from the panel.
